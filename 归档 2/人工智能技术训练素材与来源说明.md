# DocFusion-AI 人工智能技术训练素材与来源说明

## 一、说明原则

本项目使用了人工智能技术，但需要如实说明其方式。DocFusion-AI 当前并不是“从零训练基础大模型”的项目，也没有在仓库中保存大规模参数训练代码。项目的人工智能能力主要体现在三个层面：一是调用兼容 OpenAI 接口的大语言模型完成字段理解、表头对齐和局部结构化判断；二是使用句向量模型做字段语义匹配；三是基于项目自有测试素材进行规则设计、提示词调优、字段别名归纳和回归评测。因此，这里所说的“训练素材”，更准确的表述应为“用于模型调用调优、提示工程设计、规则构建和评测验证的素材集合”。

## 二、素材用途分类

项目中的素材主要服务于以下几类任务。

第一类是文档解析验证素材。其目标是检验 `docx/xlsx/md/txt` 文件能否被系统稳定解析为统一 JSON 结构，包括段落、表格和原始文本。

第二类是字段抽取调优素材。其目标是支持“分类、指标、数值、单位、时间、同比”等槽位在文本和表格中的抽取规则设计，观察不同字段名、别名和文档结构下的抽取效果。

第三类是表头映射和相似表达识别素材。其目标是帮助系统判断“用户输入表头”和“原始表头”并不完全一致时的对应关系，例如“招考生人数”与“招考人数”、“职位名称”与“招考职位”等。

第四类是回归测试素材。其目标是每次优化代码后，使用同一批样例重新执行，比较抽取结果变化，避免修复一个问题时引入新的回归错误。

## 三、素材目录与构成

当前项目中与人工智能调优直接相关的素材主要来自以下目录。

### 1. `test_data/fixtures/`

这是当前主干代码使用的正式测试样例目录，也是最重要的调优与验证素材来源。目录中包含四类文件：

- `test_data/fixtures/Excel/2025年国考职位表（节选）.xlsx`
- `test_data/fixtures/Excel/2025山东省环境空气质量监测数据信息.xlsx`
- `test_data/fixtures/Excel/COVID-19全球数据集（节选）.xlsx`
- `test_data/fixtures/Excel/电商销售数据.xlsx`
- `test_data/fixtures/Excel/糖尿病患者数据.xlsx`

- `test_data/fixtures/txt/2024年国民经济和社会发展统计公报（节选）.txt`
- `test_data/fixtures/txt/2024年药品流通行业运行统计分析报告.txt`
- `test_data/fixtures/txt/合肥市2024年国民经济和社会发展统计公报.txt`

- `test_data/fixtures/md/2023年文化和旅游发展统计公报.md`
- `test_data/fixtures/md/2024年卫生健康事业发展统计公报.md`
- `test_data/fixtures/md/第三次全国工业普查主要数据公报.md`

- `test_data/fixtures/word/2021年民政事业发展统计公报.docx`
- `test_data/fixtures/word/2022~2023年度人力资源和社会保障.docx`
- `test_data/fixtures/word/2024年杭州市生态环境状况公报（节选）.docx`
- `test_data/fixtures/word/东莞市2023~2024年国民经济和社会发展统计公报汇总.docx`
- `test_data/fixtures/word/南京市2021~2024年国民经济和社会发展统计公报汇总.docx`

这些素材覆盖了统计公报、公共管理、医疗健康、环境监测、岗位招录、商业交易和疾病数据等多种题材，既包含结构清晰的表格，也包含长篇连续文本，因此非常适合作为系统调优和评测样本。

### 2. `legacy/ok/test_docs/`

这是历史算法阶段使用的测试文档目录，和当前 `test_data/fixtures/` 具有较高重合度，但保留了早期实验版本的输入样本。该目录的重要性在于，它记录了项目从早期解析实验到当前统一主干的演进过程，可作为历史对照素材。

### 3. `legacy/ok/output_json/`

该目录保存了历史阶段对测试文档的解析输出 JSON 结果。例如：

- `legacy/ok/output_json/Excel_2025年国考职位表（节选）_xlsx.json`
- `legacy/ok/output_json/txt_2024年国民经济和社会发展统计公报（节选）_txt.json`
- `legacy/ok/output_json/word_2021年民政事业发展统计公报_docx.json`

这些历史输出虽然不是“训练数据集”本身，但对于规则迭代非常有价值。开发者可以把当前版本输出和历史输出对照，分析解析结构变化、字段缺失情况和兼容性改进效果。

### 4. `tools/cases/`

该目录保存了面向测试样例的字段配置文件，是人工智能调优过程中的重要辅助素材。典型示例如下：

- `tools/cases/xlsx_gk_positions.json`
- `tools/cases/non_table_stats.json`
- `tools/cases/non_table_hrss_eval.json`

这些配置文件定义了“用户表头 + 槽位 + 别名”的任务模板。它们不是原始语料，但直接影响模型提示词、规则路径和抽取目标，是系统进行字段级验证时不可或缺的配置素材。

## 四、素材来源说明

从来源属性看，项目中的主要素材以公开可获得的文档样例为主，包括公开统计公报、公开岗位表、公共数据表和教学演示用结构化数据。它们不是用户隐私数据，也不是项目运行中自动抓取的网络黑箱数据，而是开发阶段整理、归档并纳入仓库管理的本地样例文件。

其中，统计公报类文档通常来源于政府、行业或公共机构发布的公开报告；岗位表类文档来源于公开招录信息样例；环境和疫情数据属于公开数据表达形式样例；电商销售、糖尿病患者等表格更偏向教学与算法验证用途，用于测试系统面对不同列结构时的泛化能力。

需要特别说明的是，本项目仓库中已经保存的是“本地测试样本文件”，而不是对应的外部网页抓取脚本或原站链接。因此，在比赛文档中，建议将来源描述为“公开样例文档、公开统计报告与项目整理测试集”，并在附件中列出本地文件清单，而不是夸大为大规模互联网爬取语料。

## 五、素材在人工智能流程中的具体作用

### 1. 大语言模型提示词与表头对齐

在 `backend/app/services/llm_client.py` 和 `backend/app/api/_extract_engine.py` 的协同处理中，大语言模型可用于字段描述生成、表头映射判断和复杂文本片段理解。此时输入给模型的上下文并不是全量训练语料，而是由项目素材中抽取出的局部段落、表头候选、样例值和字段配置。

例如在表格抽取中，系统会把用户输入字段、字段别名、槽位信息和原始表头候选组合成提示，要求模型判断最可能对应的原表头。这一能力的验证依赖于国考职位表、环境监测表和疫情数据表等实际样例。

### 2. 字段别名和槽位规则构建

`_extract_config.py` 中的槽位推断和 `_extract_engine.py` 中的字段别名、模式词、时间词、同比词等规则，并非凭空生成，而是通过对现有样例文档的观察总结得到。例如“地区、行业、对象”更常归为分类，“金额、数量、规模”更常归为数值，“同比、增速、增长率”更常归为同比。这样的规则设计直接来自测试素材的语言分布。

### 3. 回归评测与误差分析

项目提供 `tools/run_extract_case.py` 作为测试入口，能够基于给定文件和字段配置自动跑通上传、解析和抽取流程。开发者每次修改算法后，都可以使用同一批素材进行回归测试，统计结果数量、字段填充率和示例输出，从而判断优化是否真实有效。

## 六、素材优势与局限

当前素材体系的优势在于格式多样、题材较广、便于重复验证，能够支撑项目原型阶段的算法设计和比赛展示。同时，表格类素材较强，有助于验证表头映射和按列抽取的稳定性。

局限也很明确。第一，规模仍然偏小，尚不足以支撑严格意义上的监督学习训练；第二，非表格文本的领域覆盖还不够广，导致文本抽取规则在新文档上仍有波动；第三，部分素材偏统计公报风格，业务文本、合同、通知、制度文件等类型覆盖不足。

因此，后续如需进一步提升系统泛化能力，建议在保持公开、可使用、可复现前提下，逐步扩充更多公共领域样例，并建立更细的标注与评测机制。

## 七、结论

综上，DocFusion-AI 所使用的人工智能训练素材，本质上是项目自建的“调优与评测素材库”。其主要来源是仓库内的公开样例文档、历史测试文档、历史输出结果和字段配置文件。这些素材并未用于从头训练基础模型，而是用于大模型提示工程、字段规则构建、表头映射验证、语义匹配调优和回归测试。这样的表述更符合当前项目真实实现，也更有利于在比赛或答辩中进行准确说明。
