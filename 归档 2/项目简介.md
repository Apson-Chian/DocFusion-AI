# DocFusion-AI 项目简介

## 一、项目概述

DocFusion-AI 是一个面向多类型文档的智能理解与结构化抽取系统，目标是把分散在文本、表格和半结构化材料中的关键信息自动整理为统一、可复用、可追溯的数据结果。项目当前支持 `txt`、`md`、`docx`、`xlsx` 四类常见文件，能够完成文档上传、结构解析、字段抽取、标准字段匹配、结果展示与来源追踪等完整流程，适用于统计公报解析、业务报表抽取、岗位表信息整理、模板填报前处理等典型场景。

本项目的核心问题并不是“读取文件”本身，而是解决不同文档格式、不同写作方式、不同表头表达带来的理解差异。传统方案通常需要针对每种模板单独写规则，维护成本高、迁移性差。一旦表头变了、段落顺序变了或者同一个字段换了说法，系统就容易失效。DocFusion-AI 试图通过“统一解析结构 + 槽位化字段配置 + 大模型语义判断 + 规则校验回退”的方式，提高跨文档类型、跨表达方式的信息抽取能力。

从系统定位看，DocFusion-AI 不是单纯的 OCR 工具，也不是单纯的文本分类器，而是一个以“文档理解和结构化输出”为中心的轻量级智能处理平台。它既保留了规则系统在可控性和可追溯性上的优势，又引入了大语言模型在语义理解、表头对齐、字段解释和复杂句式抽取中的能力，使系统在面对统计公报、综合报告、公开表格数据等复杂材料时，具有更好的适配性。

## 二、建设目标

项目建设围绕四个目标展开。

第一，统一文档输入。系统需要把不同来源、不同格式的文件转化为统一的内部结构，包括 `doc_id`、`doc_type`、`paragraphs`、`tables`、`table_views`、`raw_text` 等字段，为后续抽取和展示提供共同基础。

第二，支持用户自定义抽取目标。前端允许用户输入表头并指定槽位，例如“分类、指标、数值、单位、时间、同比”等。后端不再把抽取逻辑写死在固定字段上，而是依据用户配置动态执行抽取任务，从而增强系统的复用能力。

第三，兼顾表格和非表格场景。对于 `xlsx` 这类结构明确的表格型文件，系统采用“表头对齐 + 按列抽取”的稳定流程；对于 `txt`、`md`、`docx` 等非表格型文档，则采用“段落切分 + 语义片段识别 + 字段槽位抽取”的方式进行处理。

第四，保证结果可解释、可追踪。每条抽取结果不只返回字段值，还会保留来源段落、来源单元格、表头名称、定位坐标、原文证据等辅助信息，便于用户核验，也便于后续模板填写和质量评估。

## 三、系统组成

项目采用前后端分离但统一部署的轻量架构。前端位于 `frontend/`，主要负责字段配置、文件上传、进度展示、结果查看和新手指导；后端位于 `backend/app/`，基于 FastAPI 实现，负责解析、抽取、匹配、任务管理和数据存储。数据库使用 SQLite，便于本地开发、原型验证和比赛演示。

整体处理流程为：用户在前端配置待抽取字段并上传文件，后端先创建任务并写入数据库；随后执行解析模块，把文档转为统一 JSON 结构；再执行抽取模块，根据文件类型和字段配置生成结构化结果；最后视情况进入标准字段匹配流程，将抽取结果映射为统一业务字段。任务状态、进度百分比和错误信息会实时写回数据库，前端轮询读取并更新界面。

## 四、核心能力

在文档解析方面，系统支持对 Word、Excel、Markdown、纯文本四类文件的统一处理。针对 `docx`，系统提供 `python-docx` 解析和手动解压 XML 的双重路径，能应对部分结构异常文件；针对 `xlsx`，系统同时支持 `openpyxl` 和 `python-calamine` 回退读取，增强兼容性；针对文本类文件，系统会执行基础清洗、编码容错和段落整理。

在字段抽取方面，系统不是简单做全文关键词搜索，而是根据用户表头建立字段任务，再结合字段槽位进行结构化输出。对于文本类文档，系统会对段落进行二次切分，识别更细粒度的语义片段，再围绕字段别名、数值模式、日期表达、同比词汇等特征进行抽取。对于表格类文档，系统会优先识别用户输入字段与原始表头的对应关系，再按列逐行抽取，以避免传统“候选项竞争”带来的字段丢失问题。

在结果展示方面，系统提供字段值、字段来源、原始上下文和表格定位信息，支持用户查看一条结果是从哪一段文字或哪一个单元格得到的。这一点对统计类文档尤其重要，因为很多字段值在业务上必须可回查，不能只给出“黑箱式答案”。

## 五、项目应用价值

DocFusion-AI 的直接价值在于降低文档数据整理的人力成本。以统计公报、岗位表、公共数据表、行业运行报告为例，人工通常需要先通读文档，再查找对应字段，最后逐项录入表格。这个过程费时、重复且容易遗漏。系统通过自动抽取和结果预结构化，可以显著减少人工筛查范围，让人工工作从“全量搬运”转为“重点校核”。

从技术验证角度看，本项目也具有较强的工程意义。它展示了大模型技术在具体业务原型中的一种务实落地方式：不盲目追求端到端全自动，而是在文档解析、字段抽取、语义匹配和结果回溯之间建立稳定的分层结构。这样既能利用大模型的理解能力，又能保留规则系统的可控性和工程可维护性。

从扩展性看，项目采用字段配置驱动方式，可以继续扩展到招投标文件、企事业报表、教育统计材料、医疗统计资料等更多场景。只要增加对应的测试素材、字段配置和若干领域规则，就可以逐步沉淀形成更强的行业适配能力。

## 六、当前实现特点

当前代码已经具备较完整的比赛原型条件。后端主链路集中在 `backend/app/api/upload.py`、`parse.py`、`extract.py`、`match.py`，任务流清晰；文档解析实现位于 `backend/app/services/document_parser.py`；抽取主逻辑位于 `backend/app/api/_extract_engine.py`；前端支持自定义字段、槽位选择、任务轮询和结果查看。项目还保留了 `legacy/` 目录中的历史实验代码和旧版输出结果，便于对比迭代。

尤其值得指出的是，项目在表格抽取上已经形成针对性优化方案。对于用户配置的表头，系统会优先执行“用户字段到原始表头”的语义映射，再开展按列抽取，这比简单依赖字段候选竞争更加稳定，也更符合实际表格数据处理逻辑。

## 七、总结

总体而言，DocFusion-AI 是一个围绕“多源文档信息结构化”构建的智能处理项目，兼具原型实用性和技术探索性。它通过统一解析、动态字段配置、规则与大模型协同抽取、结果可追溯展示等机制，解决了多类型文档信息难以复用、人工整理成本高、抽取流程缺乏解释性等问题。项目当前已经具备可演示、可测试、可继续优化的完整基础，为后续进一步提升非表格文本抽取精度、扩充行业场景和沉淀标准字段体系提供了良好起点。
